## Multilevel File Ignoring System in Git

File ignoring in a repository can be configured at several levels, each of which has its own features:

1. **Global Level**: Ignoring files for all repositories on the computer. This is configured in a configuration file that applies to all of the user's repositories.

2. **Repository Level**: Ignoring files for a specific repository, which applies to all users working on that project. The settings are stored in the `.gitignore` file located in the root folder of the repository.

3. **User Level**: Ignoring files only for a specific user and their working directory in the repository. These settings are defined through the `.git/info/exclude` file, which is not included in version control and is only available locally for that user.

This multilevel system allows for flexible management of file exclusions from version control depending on your needs.

### Setting Up gitignore at the Global Level

You need to create a `.gitignore` file just like you do for each repository. Typically, it is created in the home directory, but it can be placed anywhere on the computer.

After creating the file, you need to inform Git where the global gitignore is located:
```
git config --global core.excludesfile <path_to_file>/.gitignore
```

### Repository Level gitignore Settings

The `.gitignore` file is a rule for all project participants that tells Git which files to ignore in the repository. These settings apply to all users working with this repository.

This is exactly the `.gitignore` located at the root of the repository. It should primarily include only those items that are directly related to the project and its architecture. For instance, if all project participants have a directory with local data or passwords, or if temporary files are created in the same location for everyone, and these rules are relevant to all project participants, then it makes sense to include these ignoring rules in the `.gitignore` that will be shared with the repository.

I used to think that everyone should have their own **.gitignore** and that it shouldn't be committed, but it turns out it should be so that all participants in the project have the same files and folders ignored.

### Setting Up gitignore at the User Level

This approach allows a user to ignore files and directories in Git **exclusively for their local working copy of the repository**. This is useful if you need to exclude temporary files that are generated by this user personally (for example, editor files, local builds, logs, etc.) without affecting the settings of other project participants.

The main advantages of using `.git/info/exclude` include:

1. **Locality**: This file only affects the current repository on the local machine and does not apply to other users.
2. **Isolation**: Ignoring settings remain private and do not impact collaboration in the repository.

This approach is suitable for users who want to maintain their local settings without disrupting the team’s common agreements.

## Examples of Writing Rules and Exclusions in the gitignore File

Rules in `.gitignore` can be both simple and complex, allowing for precise configuration of Git's behavior.

Below are examples of different file ignoring rules in Git and their explanations:
```bash
# comment — this line is ignored

# do not track files whose names end with .a
*.a

# BUT track the file lib.a, even though we ignore all .a files with the previous rule
!lib.a

# ignore only the TODO file located in the root directory, does not apply to files with the same name in subdirectories, e.g., subdir/TODO
/TODO
# ignore all files in the build/ directory
build/
# ignore doc/notes.txt, but not doc/server/arch.txt
doc/*.txt
# ignore all .txt files in the doc/ directory and its subdirectories
doc/**/*.txt
```

In the `.gitignore` file, you must specify relative paths. These paths are specified **relative to the root directory of your repository** (the directory where the `.git` folder is located).

To ignore a file or folder in the root directory:
```
secret.txt 
/build/
```
This ignores the file `secret.txt` and the folder `build`, which are located at the root of the repository.

## What to Do if Files Continue to Be Tracked After Adding to gitignore

If you add a folder to `.gitignore`, but `git status` still shows changes in the files of that folder, it is because Git is already tracking those files (meaning they were added to the repository before you included them in `.gitignore`).

Git will not automatically stop tracking files that have already been added. To fix this, you need to follow a few steps:

#### 1. Stop Tracking Files Already in the Repository
Use the `git rm` command with the `--cached` flag to remove the files from the index (i.e., stop tracking them) without physically deleting them from disk:

```
git rm -r --cached folder_name/
```

This command removes all files from the specified folder from the index (the index is the area where Git keeps information on which files are tracked). The files will remain on disk, but Git will stop tracking them.

#### 2. Commit Changes

After you stop tracking the files, you need to commit the changes:

```
git commit -m "Stopped tracking folder"
```

Now Git will stop tracking the files in this folder, and `.gitignore` will start to work correctly for this folder.

## Temporarily Ignoring Changes in a File

In Git, there exists a command that allows you to **temporarily stop tracking changes** in a file that is already being tracked.

When using this command for a specific file, Git will "assume" that this file remains unchanged and will not display it in the list of modified files when running the `git status` command, even if there have been local changes to the file.

==This is useful when you need to modify a file only for local work without affecting the main version of the file in the repository.==

To temporarily ignore changes in a file, you can use the command:
```
git update-index --assume-unchanged <file>
```

To disable it, use the command:
```
git update-index --no-assume-unchanged <file>
```

## Useful Commands Related to Ignoring Files in the Repository

To view what is in the **.gitignore** file at the repository level:
```
git status --ignored
```
