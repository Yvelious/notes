В командах для запуска Webpack часто используют флаг **`--mode`** или другой флаг **`--node-env`**. На первый взгляд они похожи: оба могут изменять переменную окружения **`NODE_ENV`**, и с их помощью можно создавать условия внутри конфигурации Webpack.

Несмотря на схожесть, между ними есть важные различия. Давайте разберёмся, в чём именно. Но сначала начнем с того что это за переменная `NODE_ENV` и зачем она нужна.

---

### Что такое `NODE_ENV` и зачем она нужна

**`NODE_ENV`** — это переменная окружения, которая определяет среду выполнения приложения.  
На практике она чаще всего принимает значения:

- **`development`** — режим разработки (отладка, отсутствие минификации, подробные сообщения об ошибках)
    
- **`production`** — режим продакшена (оптимизации, минификация, удаление неиспользуемого кода)
    
- любое другое значение (например, **`test`**, **`staging`**) для кастомных сценариев
    

Эта переменная позволяет менять поведение приложения в зависимости от среды — например, подключать разные плагины или изменять логику сборки.

---

### Как работает `--mode`

Если нужно, чтобы сборка вела себя по-разному в зависимости от режима, используется флаг **`--mode`** со значениями:

- `development`
- `production`
- `none`
    
Этот флаг автоматически устанавливает `process.env.NODE_ENV` в соответствующее значение и включает готовый набор оптимизаций для выбранного режима.


```js
module.exports = (env, argv) => {   
	const isProduction = argv.mode === 'production';    
	return {     
		entry: './src/index.js',     
		plugins: [ isProduction && new CleanWebpackPlugin()]   
	}; 
};
```

В этом примере переменная `isProduction` определяется через `argv.mode`, который Webpack передаёт в конфиг в зависимости от значения указанного в флаге `-mode`.


### Как работает `--node-env`



Флаг **`--node-env`** напрямую устанавливает переменную окружения `process.env.NODE_ENV` в указанное значение.  
В отличие от `--mode`, он не ограничен только `development` и `production`. Можно указать, например, `test` или `staging`.

Пример команды запуска:

```js
webpack --node-env=test
```

**N.B.**
Можно назначить значение переменной окружения **`NODE_ENV`** без использования флага `--node-env`, как в примере ниже:
```bash
NODE_ENV=test webpack
```
Но это не будет кросс-платформенным решением, так как в Windows нужно использовать `set NODE_ENV=test && webpack`, а в Unix-подобных системах — `NODE_ENV=test webpack`. Поэтому лучше использовать флаг `--node-env` для кросс-платформенности.
``

```js

Однако `--node-env` **не включает оптимизации автоматически** — их нужно прописывать вручную.

```js

const isTest = process.env.NODE_ENV === 'test';  
module.exports = {   
plugins: [ isTest && new SomeTestPlugin()] 
};
```

В этом случае переменная `isTest` доступна в любом месте конфигурации, так как `process.env.NODE_ENV` глобальна.

N.B.
Если мы используем `--node-env` , но все же хотим что бы сработала при сборке автоматическая оптимизация для продакшена как если бы мы использовали флаг `--mode` cо значением `production`, то нам нужно явно прописать в конфигурации ключ `mode` и установить его значение в `production`:

```js
const isProd = process.env.NODE_ENV === 'production';  
module.exports = {  
    mode: isProd ? "production" : "development",
    ...
}
```

### Сравнительная таблица

|Критерий|**`--mode`**|**`--node-env`**|
|---|---|---|
|**Доступные значения**|`development`, `production`, `none`|Любое (`development`, `production`, `test`, `staging` и др.)|
|**Устанавливает `process.env.NODE_ENV`**|Да|Да|
|**Включает оптимизации**|Да, для `production` (минификация, tree-shaking, удаление неиспользуемого кода)|Нет, нужно настраивать вручную|
|**Как получить значение в конфиге**|Через `argv.mode` внутри функции `module.exports`|Через `process.env.NODE_ENV` в любом месте файла|
|**Основное применение**|Быстро переключать сборку между режимами разработки и продакшена с готовыми оптимизациями|Гибкая настройка среды (тесты, staging, кастомные сценарии)|
|**Пример команды**|`webpack --mode production`|`webpack --node-env=test`|

### Резюмирую

- Используйте **`--mode`**, если вам нужно быстро переключаться между разработкой и продакшеном с автоматическими оптимизациями.
- Используйте **`--node-env`**, если вы хотите задать кастомное значение среды (например, `test` или `staging`) и настроить поведение сборки вручную.

> В командах для запуска Webpack часто используют флаги **`--mode`** или  другой флаг **`--node-env`**. Эти флаги схожие между собой, они оба могут изменять переменную окружения **`NODE_ENV`**, и при помощи обоих  можно создавать условия внутри конфигурации Webpack. Несмотря на их схожесть, между этими флагами есть важные различия. И сейчас мы в этом разберёмся.
> 
> **Начнем с того  что эта за переменная  `NODE_ENV` и зачем он нужна.**
> **`NODE_ENV`** — это переменная окружения, которая используется для определения среды выполнения приложения. Она может принимать значения, такие как **`development`**, **`production`** и любое другое значение  Эта переменная позволяет разработчикам настраивать поведение приложения в зависимости от среды.
> 
> **Теперь давайте рассмотрим, как работают оба флага:**
> 
> 
> Ecли вам нужно настроить конфигурацию так, чтобы она вела себя по-разному в зависимости от того, в каком режиме (разработка или продакшен) происходит сборка используется флаг --mode  со значениями **`development`** или **`production`**. Этот флаг автоматически устанавливает переменную **`process.env.NODE_ENV`** в соответствующее значение. Вы можете использовать эту переменную для условного включения или отключения плагинов и опций, написав условные конструкции в конфигурации Webpack.
> 
> Флаг **`--node-env`** используется для установки переменной окружения `process.env.NODE_ENV`, но, в отличие от флага **`--mode`**, он может принимать любое значение. Например, вы можете использовать его для установки `NODE_ENV` в значение `test` или любое другое, которое вам необходимо. Флаг `--mode` ограничен значениями `development` и `production`, тогда как `--node-env` может принимать любое значение.
> 
> 
> Также различия между ними заключаются в том, что флаг **`--mode`** автоматически включает оптимизации для продакшен-сборки, такие как минификация кода и удаление неиспользуемого кода. Флаг **`--node-env`** не включает эти оптимизации, и вам нужно будет настроить их вручную в конфигурации Webpack.
> 
> Пожалуй это и есть самый главный ньюанс между этими флагами.
> 
> Также отличия в самой конструкции использования для создание условий в конфигурации Webpack:
> 
> 
> Для mode используется такая конструкция:
> 
> ```js
> 
> module.exports = (env, argv) => {
>   const isProduction = argv.mode === 'production';
> 
>   return {
>     entry: './src/index.js',
>     plugins: [
>       // Этот плагин будет использоваться только в режиме продакшена
>       isProduction && new CleanWebpackPlugin()
>     ]
>   };
> };
> ```
> 
> Модуль экспортирует функцию, которая принимает два аргумента: `env` и `argv`. Аргумент `argv` содержит информацию о режиме сборки, который был указан при запуске Webpack. Мы проверяем, является ли режим продакшеном, и на основе этого устанавливаем переменную `isProduction`.
> Как видите переменная `isProduction` устанавливается на основе значения `argv.mode`, которое автоматически устанавливается Webpack в зависимости от флага **`--mode`**. Внутри модуля утанавливается режим сборки, и на основе этого можно включать или отключать плагины и другие настройки.
> 
> 
> 
> 
> 
> 
> 
> Для node-env используется конструкция:
> 
> Мы можем объявить переменную `isProduction` на основе значения `process.env.NODE_ENV`, которое устанавливается при запуске Webpack с флагом **`--node-env`**. И эта переменную можно объявить выше модульного экспорта, чтобы использовать её в конфигурации Webpack.
> 
> ```js
> const isTest = process.env.NODE_ENV === 'test';
> 
> module.exports = {
>   // ...
>   plugins: [
>     // Плагин будет добавлен только в режиме test
>     isTest && new SomeTestPlugin()
>   ]
> };
> ```
> 
> 
> Резюмиру.
> Различия между флагами **`--mode`** и **`--node-env`** заключаются в следующем:
> 1. --node-env может принимать любое значение, в то время как --mode ограничен значениями development и production.
> 2. Флаг --mode автоматически включает оптимизации для продакшен-сборки, тогда как --node-env не делает этого.
> 3.  Присвоить значение из опции --mode можно через `argv.mode` внутри  функции, которая экспортируется из модуля, а для --node-env используется `process.env.NODE_ENV`, которое доступно в любом месте конфигурации.
> 4. Конструкция для создания условий в конфигурации Webpack отличается: для **`--mode`** используется `argv.mode`, а для **`--node-env`** — `process.env.NODE_ENV`.
