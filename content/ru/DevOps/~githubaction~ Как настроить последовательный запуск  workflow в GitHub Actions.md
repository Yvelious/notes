При работе с GitHub Actions часто возникает ситуация, когда в репозитории настроено несколько workflow, и важно, чтобы они выполнялись в определённом порядке.

Например:
- сначала должен выполниться `build`
- и только после его успешного завершения должен запускаться `deploy`

Однако по умолчанию, если несколько workflow подписаны на одно и то же событие (например, `push` в ветку `main`), они запускаются **параллельно**. Это может привести к проблемам, если второй workflow зависит от результата первого.

Разберём как правильно настроить **последовательный запуск workflow в GitHub Actions**.

## Проблема параллельного запуска

Допустим, у нас есть два workflow:

- `build.yml`
- `deploy.yml`

Оба настроены на событие `push` в ветку `main`:

```
on:
  push:
    branches: [ main ]

```

При каждом `git push` они будут запускаться одновременно.  
Если `deploy` зависит от результата `build`, это может привести к ошибкам:

- деплой начнётся до завершения сборки
- не будут готовы артефакты
- тесты могут ещё выполняться
- окружение может быть не готово

Поэтому порядок выполнения нужно задать явно.

## Последовательный запуск через `workflow_run`

В GitHub Actions есть специальное событие `workflow_run`, которое позволяет запускать один workflow после завершения другого.


### Первый workflow — `build.yml`

```yaml
name: Build

on:
  push:
    branches: [ main ]

jobs:
  ...

```

Этот workflow запускается при каждом push в `main` и выполняет jobs, например, сборку и тестирование.

### Второй workflow — `deploy.yml`

```yaml
name: Deploy

on:
  workflow_run:
    workflows: ["Build"]
    types:
      - completed

jobs:
  deploy:
    if: ${{ github.event.workflow_run.conclusion == 'success' }}
    ...
```

Этот workflow запускается **только после завершения** workflow `Build`. А также с условием, что `Build` завершился успешно.

## Как это работает

Теперь процесс выглядит так:

1. Делаем `git push` в ветку `main`
2. Запускается workflow `Build`
3. После его завершения GitHub автоматически запускает `Deploy`
4. Если `Build` завершился с ошибкой — `Deploy` не запустится

Таким образом, достигается строгая последовательность:

```
push → build → deploy
```


## Когда стоит использовать такой подход

Последовательный запуск workflow полезен, если:

- деплой зависит от сборки
- тесты должны завершиться до публикации
- есть миграции базы данных
- используется несколько стадий пайплайн

## Резюмирую

Если в проекте используется несколько GitHub Actions workflow и между ними есть логическая зависимость, то их необходимо запускать последовательно.
Лучший и официальный способ сделать это — использовать событие `workflow_run`.

Это позволяет:
- гарантировать порядок выполнения
- защитить продакшн от некорректных деплоев
- построить полноценный CI/CD пайплайн
