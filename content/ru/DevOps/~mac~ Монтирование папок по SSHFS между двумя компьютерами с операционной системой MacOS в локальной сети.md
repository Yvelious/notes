Если у вас есть два компьютера под управлением **macOS**, вы можете подключить одну из папок с одного Mac на другой с помощью **SSHFS**. Это позволит работать с удалёнными файлами так, как будто они находятся на вашем локальном диске — удобно для разработки и распределения задач между несколькими машинами, обмена данными и резервного копирования.

Наша стратегия: Первый Mac (локальный) подключается к удалённой папке на втором Mac по SSH и монтирует её в локальную директорию.

![[Pasted image 20250708133015.png | 700]]


## Установка SSHFS на первом компьютере (тот, с которого будет доступ)

Откройте терминал и выполните следующие команды:
```bash
brew install macfuse 
brew tap gromgit/fuse 
brew install gromgit/fuse/sshfs-mac
```
Эти команды устанавливают необходимые компоненты: `macFUSE` и сам `sshfs-mac`.

## Включение SSH-доступа на втором компьютере (тот, к которому подключаемся)
- Зайдите в `System Settings → Sharing`
- Включите **Remote Login**
- Убедитесь, что ваш основной пользователь имеет доступ по SSH

```bash
ssh your_login_second_pc@your_ip_second_pc
```

Если подключается — всё готово.


## Подготовка папок

**На втором Mac** (удалённом):
Создайте папку, которую хотите расшарить:
```bash
mkdir ~/remote-folder
```

**На первом Mac** (локальном):
Создайте папку, в которую будет монтироваться удалённая:
```bash
mkdir ~/remote
```

## Монтирование папки через SSHFS на первом компьютере
Теперь можно смонтировать удалённую папку на первом Mac. Выполните в терминале следующую команду:

```bash
sshfs your_login_second_pc@your_ip_second_pc:~/remote-project ~/remote -o allow_other,default_permissions,reconnect
```

Эта команда монтирует удалённую папку `remote-project` с другого Mac в локальную папку `~/remote` на первом компьютере через `sshfs`.
Опции которые используются в команде:

| Опция                 | Назначение                                                                                                                                                                                                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `allow_other`         | Разрешает доступ к смонтированной папке **не только пользователю, который выполнил монтирование**, но и другим пользователям системы. Это нужно, например, если вы хотите, чтобы IDE (VS Code, WebStorm) могли видеть содержимое. ⚠️ Требует разрешения в `/etc/fuse.conf`. |
| `default_permissions` | Использует стандартную проверку прав доступа Unix (владелец, группы, chmod), а не только SSH. Это помогает избежать проблем, когда файлы видны, но нельзя их открыть.                                                                                                                             |
| `reconnect`           | Автоматически переподключается, если соединение по SSH временно прерывается (например, при обрыве Wi-Fi). Очень полезно, если соединение нестабильное.                                                                                                                                            |


По умолчанию опция `allow_other` может не работать, пока не будет добавлено разрешение в конфигурационный файл `fuse.conf`. Это связано с политиками безопасности macOS, которые ограничивают доступ к смонтированным файловым системам.

1. В терминале и создайте файл fuse.conf:
```bash
sudo nano /etc/fuse.conf
```

2. Добавьте строку:
```bash
user_allow_other
```

3. Сохраните файл и повторно выполните команду монтирования
```bash
sshfs your_login_second_pc@your_ip_second_pc:~/remote-project ~/remote -o allow_other,default_permissions,reconnect
```

## Как размонтировать папку

Чтобы размонтировать папку, выполните:
```bash
umount ~/Volumes/SSD/test-remote
```

Если получите ошибку `Resource busy`, попробуйте:
```bash
umount -f ~/Volumes/SSD/test-remote
```

N.B.
Если не помните название смонтированной папки, можно посмотреть список смонтированных файловых систем командой:
```bash
mount
```

> [!raw-hidden]-
> ## Автоматизируем процесс монтирования
> 
> **N.B. не заработало это у меня на маках как не пытался создается сетевой диск с помощью autofs. но конфигурация внутри fstab вызов sshfs не получается.**
> 
> Что бы каждый раз при перезагрузке Mac не выполнять команду монтирования вручную, можно использовать `fstab` и `autofs`.
> 
> ### `fstab` — это конфигурационный файл
> - Расположен по пути: `/etc/fstab`
> - Описывает, **что и куда монтировать**, и с какими параметрами
> - Используется системой для автоматического монтирования
> 
> **N.B.**
> Если этого файла нет, его можно создать вручную.
> 
> 
> ### `autofs` — это системная служба (демон)
> - Следит за `fstab` (и другими источниками)
> - **Автоматически монтирует файловые системы при обращении к ним**
> - На macOS запускается при первом доступе к папке (например, `cd ~/remote`)
> 
> ### Как они работают вместе
> 
> 1. Прописываете в `/etc/fstab`, что хотите монтировать ``sshfs``. 
> 2. `autofs` отслеживает путь, указанный в `fstab`.
> 3. Когда вы открываете эту папку — `autofs` монтирует всё автоматически.
> 
> #### Пример записи в `fstab`
> ```bash
> sshfs#your_username_second_pc@your_ip_second_pc:~/remote-project ~/remote fuse allow_other,default_permissions,reconnect 0 0
> 
> ```
> 
> 
> Если совсем коротко:
> > 🔹 `fstab` — что монтировать и как  
> > 🔹 `autofs` — монтирует при доступе к папке
> 
> **N.B.** 
> Демон `autofs` монтирует папки **только при первом обращении** к папке. То есть, если вы просто добавите запись в `fstab`, но не откроете папку, она не будет смонтирована до тех пор, пока вы не попытаетесь получить к ней доступ(зайти в нее). К примеру, если у нас добавлена конфигурация в `fstab`, но мы никак не обратились еще к папке(через терминал или через Finder), то папка не будет смонтирована пока к ней не обратяться.
> 
> 
> 
> ### Применение изменений конфигураций в  `fstab`
> Что бы демон `autofs` считал конфигурацию, которая находится в fstab. Нужно единожды запустить команду `sudo automount -vc`
> Эту команду нужно запускать только один раз когда мы создали или изменили конфигурацию в `fstab`.
> 
> 
> Демон `autofs` читает конфигурационный файл`fstab` **только при старте или при вызове `automount`**. Без команды `automount -vc`  пришлось бы **перезагружать Mac**, чтобы `autofs` увидел изменения в `fstab`.  Команда`sudo automount -vc` — это способ **мягко перезапустить `autofs`** и сразу применить изменения из конфигурационного файла`fstab` без перезагрузки.
> 
> **Что обозначают аргументы команды `automount -vc`:**
> 
> |Аргумент|Значение|
> |---|---|
> |`-v`|verbose — показывает, что делает команда (отладка)|
> |`-c`|cache reset — сбрасывает кэш автосмонтированных точек|
> **N.B.** 
> Команда `automount -vc` не является обязательной, но она **помогает применить изменения в конфигурации `fstab` без перезагрузки системы**.
> 
> ### Проверка активности `autofs`
> 
> Демон **`automountd` работает всегда по умолчанию** на macOS как системная служба. Но если мы хотим убедиться в его работе то можем выполнить команду, которая покажет, что он запущен и слушает запросы на монтирование.
> 
> В терминале выполнить команду
> ```bash
> ps aux | grep automountd
> ```
> 
> Если служба работает, то  мы увидим примернот такую строку:
> ```bash
> root       123   0.0  0.1  2433984   8208     Ss    1:20PM   0:00.02 /usr/sbin/automountd
> ```
> Это значит, что `autofs` активен и слушает запросы.

> ### ✨ Вариант 2 — вручную монтировать (не через fstab)
> 
> Если хочешь полный контроль и надёжность, **не используй `fstab`**, а сделай свой скрипт монтирования.
> 
> bash
> 
> CopyEdit
> 
> `#!/bin/bash MOUNTPOINT="/Volumes/SSD/test-remote" mkdir -p "$MOUNTPOINT" sshfs levy@192.168.178.54:/Volumes/SSD/mbp2011-test "$MOUNTPOINT" \   -o allow_other,default_permissions,reconnect,IdentityFile=/Users/levy/.ssh/mbp-2011/id_ed25519`
> 
> Добавь в автозагрузку (через LaunchAgent или `cron @reboot`), и будет работать стабильнее, чем `fstab`.


## Резюмирую
Использование `sshfs` между двумя Mac — это простой способ организовать общий доступ к файлам без необходимости синхронизации или настройки сетевого диска. Особенно удобно для разработчиков, работающих с несколькими машинами в локальной сети. Используя `sshfs` вы можете работать с удалённой папкой так, как будто она находится на вашем локальном компьютере.
