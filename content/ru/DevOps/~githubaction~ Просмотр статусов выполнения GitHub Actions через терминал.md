Каждый раз заходить на GitHub через web-интерфейс, чтобы отслеживать выполнение GitHub Actions, не слишком удобно — особенно если ты часто делаешь push и хочешь сразу видеть результат CI.

Гораздо удобнее мониторить выполнение GitHub Actions прямо из терминала, не открывая браузер. К счастью, GitHub предоставляет для этого официальный инструмент — **GitHub CLI**.

В этой статье разберём, как смотреть статус GitHub Actions, логи и прогресс выполнения прямо из консоли.


## Установка GitHub CLI

Для начала нужно установить GitHub CLI.

Официальный сайт:  
[https://cli.github.com/](https://cli.github.com/)

На macOS удобнее всего установить через Homebrew:
```bash
brew install gh
```

После установки нужно авторизоваться в своём GitHub-аккаунте:
```bash
gh auth login
```

Выбираем cпособ авторизации:
- GitHub.com
- HTTPS
- Login with browser

После успешной авторизации CLI получит доступ к твоим репозиториям и GitHub Actions.


## Просмотр списка GitHub Actions

Чтобы посмотреть список всех запусков GitHub Actions в репозитории, используется команда:
```bash
gh run list
```

![[Pasted image 20260108200706.png]]

Она покажет последние запуски с информацией о:
- статусе (`queued`, `in_progress`, `completed`)
- результате (`success`, `failure`, `cancelled`)
- workflow
- ветке
- и т.д.

## Фильтрация и форматирование вывода

По умолчанию команда `gh run list` выводит список запусков в стандартном табличном виде.  
Однако часто нужно видеть только последние запуски и только нужные поля.

### Вывод последних N запусков

Если, к примеру, нужно вывести **5 последних запусков**, можно использовать флаг `-L`:

```bash
gh run list -L 5
```


### Вывод только нужных полей

GitHub CLI позволяет получать данные в формате JSON и форматировать вывод с помощью встроенного JMESPath-запроса (`-q`).

Например, чтобы вывести **5 последних запусков** с полями:

- `databaseId`
- `status`
- `conclusion`
- `workflowName`

можно использовать команду:

```bash
gh run list -L 5 \   --json databaseId,status,conclusion,workflowName \   -q '.[] | "\(.status) | \(.conclusion // "null") | \(.workflowName) | #\(.databaseId)"'
```

В результате в терминале будет отображаться компактный список в удобном формате:

```bash
in_progress | null    | build-and-test | #59722592906 
completed   | success | deploy         | #59722592810 
completed   | failure | lint           | #59722592744
```


### Доступные поля для вывода

В `--json` можно указывать любые доступные поля. Наиболее полезные из них:
- `databaseId` — уникальный ID запуска
- `status` — текущий статус: `queued`, `in_progress`, `completed`
- `conclusion` — результат выполнения: `success`, `failure`, `cancelled` (только если `completed`)
- `workflowName` — имя workflow
- `branch` — ветка, из которой был запущен workflow
- `displayTitle` — отображаемое название запуска
    

Таким образом, с помощью `--json` и `-q` можно гибко настраивать вывод и получать именно ту информацию, которая нужна для мониторинга GitHub Actions прямо из терминала.

### Фильтрация по статусу

Можно вывести только те workflow, которые сейчас выполняются:
```bash
gh run list --status in_progress
```

Аналогично можно смотреть только ожидающие в очереди:
```bash
gh run list --status queued
```


## Просмотр деталей конкретного запуска

У каждого запуска есть свой `id`. Его можно взять из вывода команды `gh run list`.
Чтобы посмотреть, как выполнился конкретный GitHub Action:
```bash
gh run view --job=59722592906
```

В терминале отобразятся все шаги workflow.
Для просмотра подробных логов каждого шага используется флаг `--log`:
```bash
gh run view --log --job=59722592906
```


## Просмотр выполнения конкретного workflow в реальном времени

Чтобы следить за выполнением GitHub Action в реальном времени, можно использовать команду:
```bash
gh run watch $(gh run list -L 1 --json databaseId -q ".[0].databaseId")
```

![[Pasted image 20260107205817.png | 700]]

Эта команда:
- берёт последний запущенный workflow
- подключается к нему
- показывает прогресс выполнения и логи в реальном времени

## Автоматизация мониторинга за Github Action

Проблема в том, что GitHub CLI не стримит события в реальном времени. Он работает через polling — то есть показывает актуальное состояние на момент запроса.
`gh run watch` просто опрашивает GitHub API с определённым интервалом и обновляет вывод. Это не push-уведомления, а периодическая проверка статуса.
Данная команда удобна когда мы следим за конкретным запущенным в workflow.  А если нам нам нужно мониторить статус 5 или 10 workflow которые запущенные, в процессе или в очереди. Тогда данная команда не особо подходит нам под наши цели.  Для этого мы можем использовать утилиту `watch`, которая позволяет запускать любую команду каждые N секунд и обновлять вывод в терминале.


## Использование утилиты watch для автоматического обновления списка GitHub Actions

`watch` — это утилита, которая позволяет запускать команду каждые N секунд и обновлять вывод в терминале.
На macOS её можно установить через Homebrew:
```bash
brew install watch
```
После этого можно запустить, например:
`watch -n 5 'gh run list -L 5'`

![[Pasted image 20260108200130.png | 900]]

**Эта команда:**
- каждые 5 секунд выполняет `gh run list -L 5`
- показывает 5 последних запусков GitHub Action в терминале
- автоматически обновляет экран

Флаг `-L 5` означает, что нас интересует 5 последних workflow.
В итоге мы получаем автоматически обновления списка GitHub Actions прямо в терминале.

## Резюмирую

**Используя GitHub CLI и стандартные консольные утилиты, можно:**
- смотреть список запусков GitHub Actions
- фильтровать по статусу
- просматривать логи
- следить за выполнением в реальном времени
- организовать автоматический мониторинг через `watch`
    
**Это позволяет работать с CI гораздо быстрее и удобнее, не переключаясь постоянно в браузер.**
